# 场景分段统一规则格式

当用户要求“统一规则”“整体规则”“每个场景分别给规则”“人物全程一致”或提供 `{{Mixed 1}}`、`{{角色A}}`、`@人物资产` 等变量时，使用本格式。

## 核心顺序

1. 按时间线识别不同地点、时间、主要光源或叙事功能形成的场景段落。
2. 每个场景段落写3—4条编号规则，只写该场景独有的拍摄、镜头、灯光、背景和表演要求。
3. 所有场景写完后，增加“整体统一规则”，用5—8条短规则集中锁定跨场不变项。
4. 如果同时交付按秒分镜，将统一规则放在分镜前，或拆成独立的“统一规则”文件；不要把规则混入每个镜头字段。

## 固定输出骨架

```markdown
# 《项目名》统一规则

## 场景段落一｜[地点/事件]（[起止时间]）

1、[项目类型、真人/动画媒介、场景时间、地点和整体拍摄质感。]

2、[主体、角色变量、焦段、景深、机位、轴线、站位和主运镜。]

3、[有物理来源的主光、补光、方向、软硬、色温、阴影和场景色彩来源。]

4、[背景地理、关键道具、动作/微表演、该段结束状态与下一段承接。]

## 场景段落二｜[地点/事件]（[起止时间]）

1、……

2、……

3、……

4、……

## 整体统一规则

- [所有角色变量的身份一致性。]
- [跨场固定发型、服装、体型、气质和道具。]
- [动作、重力、惯性、眨眼、呼吸和微表情。]
- [统一成像、肤质、手部和材质响应。]
- [统一色调及其物理来源。]
- [声音、台词、环境声和BGM规则。]
- [文字、字幕、水印和后期合成规则。]
```

## 场景规则写法

每个场景按以下信息排序，允许合并但不要打乱因果：

1. **风格与空间**：项目类型、媒介、时间、地点、空间真实度。风格词必须落到能看见的布景、材质或拍摄方法。
2. **镜头与站位**：主体优先级、角色变量、焦段、景深、机位高度、轴线、屏幕方向、运动触发。每段只保留一个主要运镜纪律。
3. **光线与色彩**：写清光源名称、方向、软硬、色温、阴影和补光；颜色必须来自墙面、服装、屏幕、灯具、天空、玻璃、植物或道具。
4. **环境与表演**：背景锚点、关键道具、动作路径、自然眨眼、呼吸和末帧承接。临时表情不得改变稳定身份。

场景段落之间可以改变景别、光线强度和情绪，但必须继承项目的成像介质、镜头家族、肤质规则、色彩主轴和角色稳定身份。

## 整体统一规则写法

- 用户提供的变量必须逐字保留，包括大小写、空格、花括号和 `@` 前缀。已知角色映射时写“`{{Mixed 1}}` 对应角色名”；未知时只使用原变量，不自行猜测。
- 明确写出角色脸部、发型、服装、体型比例和气质全程一致，不得互换，不得漂移，不得改变媒介风格。
- 动作要求写成正向可执行描述：动作丝滑流畅、符合重力和惯性、自然眨眼、呼吸、吞咽、视线微调、表情连续过渡。
- 用户要求“不要AI感”时，将其落实为真实皮肤纹理、自然关节和手指、稳定五官、连续服装纹理、正常运动模糊和物理接触反馈。
- 用户指定色调变化时，说明颜色从哪些实体来源出现，并保护肤色；例如“翠绿色上调”应来自植物、玻璃反射、屏幕、灯具或服装点缀，而不是整张画面覆绿色滤镜。
- 用户要求不生成BGM时，明确写“全片不生成任何BGM”，仅保留用户允许的同期环境声、台词、动作音和设备音；不得以“低频氛围音乐”变相添加配乐。
- 准确文字通常留出干净安全区并后期合成。用户明确要求模型直接生成文字时，再把文字内容写入镜头提示词。
- 整体部分保持简略，只写跨场不变项；场景专属灯位、构图和动作不要在整体部分重复。

## 适配原则

- 学习用户示例的结构与信息密度，不复制示例中的题材。古风示例只提供格式时，要根据源剧本改写成现代、科幻、广告或其他实际题材。
- 用户给出的具体要求优先于默认审美；存在物理冲突时，保留用户目标并改写成可实现的光源、机位或动作。
- 场景数量按实际剧情决定，不强制两段。连续地点但时间、光线或叙事任务明显改变时可以拆段；不同地点不得合并。
- 输出前检查：场景段落是否按时间排列、角色变量是否逐字一致、场景规则是否只含局部内容、整体规则是否简短且覆盖人物/动作/色彩/声音/文字。
