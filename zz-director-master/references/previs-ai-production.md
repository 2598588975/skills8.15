# 导演预演、AI 制作与成片闭环

用于把已经确认的剧本、导演定调或分镜继续推进为可执行预演、AI 视频生产计划、声音与剪辑交接，以及失败修复方案。只在任务需要站位、轴线、关键帧、跨段连续性、平台适配、剪辑或 QC 时读取。

## 目录

1. 范围与路由
2. 人物调度和轴线
3. 连续性合同
4. 关键帧与故事板策略
5. 平台控制面适配
6. 声音与剪辑
7. QC 与修复阶梯
8. 任务追踪与交付

## 1. 范围与路由

按用户真正需要的交付物工作，不自动扩成全套：

- 只问“这场戏怎么拍”：交付导演分析、调度与必要镜头。
- 只要分镜表：交付镜头表，不额外生成视频提示词。
- 只要 AI 视频提示词：内部完成调度、连续性和风险判断，只输出可直接使用的提示词及必要素材职责。
- 要完整生产方案：按“导演定调 → 节奏 → 调度 → 分镜 → 关键帧 → 视频提示词 → 声音/剪辑 → QC”推进。
- 已有失败成片：先诊断根因，再选择提示词修复、参数调整、重做关键帧、重设镜头、后期处理或删镜。

每镜必须回答：观众在这一镜结束时，比镜头开始前多知道、感到或确认了什么。没有新增叙事价值的镜头删除或合并。

## 2. 人物调度和轴线

先确定身体和空间，再决定摄影机：

1. 记录人物起始区域、身体朝向、视线目标、距离和权力位置。
2. 写清人物移动路径、接触对象、遮挡、道具交接和结束区域。
3. 建立行动轴线、人物屏幕左右和允许放置摄影机的半圆区域。
4. 为每次切镜检查轴线、视线、屏幕方向、动作方向和背景地理是否可交接。
5. 需要越轴时，使用中性机位、沿轴机位、可见的摄影机移动或人物明确换位，让观众看见空间关系改变。

镜头调度记录采用：

```text
角色A：起点 → 路径/动作 → 终点；视线目标；手中道具；屏幕方向。
角色B：起点 → 反应/阻挡 → 终点；视线目标；与A的距离变化。
摄影机：所在区域；景别；观察方向；主要运镜；停止构图。
轴线：行动轴；当前侧；是否越轴及越轴依据。
```

禁止依靠“自然走位”“激烈互动”“镜头环绕”等笼统词替代可见路线。每个普通生成单元最多一个主要人物动作、一个主要摄影机行为、一个主要环境变化和一个明确结束状态。

## 3. 连续性合同

多镜头或多段项目先建立最小连续性合同：

- `identity_lock`：人物脸部、发型、体型比例、稳定气质。
- `wardrobe_lock`：服装、鞋履、饰品、污损和湿润程度。
- `space_lock`：出入口、站位区域、轴线、屏幕方向、障碍物。
- `prop_lock`：道具所在手、朝向、数量、开合与启停状态。
- `light_lock`：动机光来源、世界方向、高度、软硬、色温与曝光。
- `audio_lock`：环境底声、声源远近、混响和声音尾点。
- `performance_lock`：当前姿势、视线、动作进度和情绪落点。

每镜同时读取规范母版与上一镜已验收结束状态：规范母版控制身份和世界规则，已验收状态控制当前姿势、位置与物理进度。未验收或已经漂移的生成结果不得成为后续承接来源。

每镜写出：

```text
continuity_in：必须接住的状态。
visible_change：本镜唯一主要变化。
continuity_out：下一镜必须继承的状态。
```

## 4. 关键帧与故事板策略

根据连续性风险选择控制方式，不把关键帧当成默认答案：

- 单一首帧：构图稳定、动作简单、结束状态不需精确控制。
- 首尾帧：存在明确变换、动作终点或构图迁移，且平台真实支持。
- 逐镜关键帧：人物身份、服装、空间或站位跨镜容易漂移。
- 故事板：需要先验证镜头顺序、轴线、视线、动作因果或视觉节奏。

静态图只承担被明确分配的身份、造型、空间、构图或风格；视频提示词继续承担动作、摄影机、时间、声音和结束状态。分镜中的格线、箭头、编号、文字和色板不得进入成片描述。

生成视频前检查关键帧：身份、双手、道具、轴线、屏幕方向、光源方向、可见动作起点和画外空间是否正确。错误关键帧先修图，不用视频提示词掩盖。

## 5. 平台控制面适配

先确认平台真实提供哪些输入：文生视频、图生视频、首尾帧、参考绑定、视频参考、原生音频、时长、延长、种子、负面提示词或镜头控制。未知时不虚构功能，使用保守通用写法。

根据控制来源选择提示词形态：

- `motion_only`：参考图已决定身份、构图和光线，文字只写动作、摄影机、时间、声音与结束状态。
- `full_description`：文字同时承担主体、场景、动作、摄影、光线、声音和约束。
- `keyframe_bridge`：首尾图已经确定，文字只描述两者之间唯一连续变化。
- `timestamped_sequence`：平台支持多镜头或用户要逐秒规划，按连续时间段写镜头。

平台参数、费用、模型 ID 和限制必须以当前官方资料或用户界面为准；创作规则不能替代平台事实核验。

## 6. 声音与剪辑

声音按需规划五层：环境底声、空间声、动作拟音、关键效果、对白/旁白。默认遵守用户个人规则：不自动生成背景音乐、字幕、标题或水印。

重要声音必须写清“来源 → 变化 → 叙事作用”。用连续环境底声、J-cut、L-cut 或声音尾点维持跨镜空间，不用无来源的冲击音效掩盖画面问题。

剪辑表至少记录：镜头顺序、建议使用区间、切入/切出点、动作或视线匹配、声音桥、转场依据和连续性风险。优先使用硬切、动作切、视线切、真实遮挡或有叙事意义的图形匹配；不默认添加擦除、融化、变形和模板化转场。

后期规划采用：

```text
镜头ID｜素材状态｜建议入点/出点｜切点依据｜声音承接｜需修复项｜是否需要重生成
```

## 7. QC 与修复阶梯

先定位根因，再改提示词：

1. 素材不一致：身份或参考源互相冲突。
2. 提示词超载：人物、动作、运镜或环境变化超过单镜容量。
3. 动作起点不清：静态姿势没有形成可运动状态。
4. 缺少结束状态：模型不知道动作何时、何处停止。
5. 摄影机与空间冲突：镜头路径穿模、越轴或与构图不相容。
6. 连续性断裂：前镜结束状态和后镜起点不一致。
7. 平台错配：要求了当前控制面并不存在的能力。

按成本从低到高修复：删冲突词 → 调整一个参数 → 单镜重生成 → 重做关键帧 → 重设或拆分镜头 → 后期修复 → 删除镜头。连续三次失败后必须改变镜头设计，不继续堆词。

每次重试只改变一个主要变量，并记录：原问题、修改变量、结果、是否成为已验收状态。

## 8. 任务追踪与交付

正式生成任务必须保存平台、模型、模式、素材映射、参数、任务 ID、终态和资源位置。没有成功终态或可用资源时，不声称已经交付文件。

对需要稳定音色的系列内容，先用一个短片段确认声音身份，再让后续片段复用同一音色锚点；当前片段的具体台词仍由当前提示词控制。用户未要求旁白或声音身份时不主动引入。

交付前确认：

- 用户已确认的剧本事实和导演决定没有被改写。
- 镜头表、关键帧、视频提示词和剪辑表使用同一角色/场景/道具名称。
- 所有跨镜状态都有明确来源。
- 输出规模与用户请求相称。
- 生成任务可追踪，失败原因和下一步清楚。
